# NSwag generates the Hyper Agent C# client at build time

The C# Application Server's Hyper Agent client (`ISidecarClient`) is generated by NSwag from the Hyper Agent's `/v1/swagger.json` (emitted by NestJS Swagger). The generated client is checked into the repo at `apps/service/src/Hyper Agent/SidecarClient.g.cs` and regenerated by a CI step on every PR that touches `apps/sidecar/`.

## Context

The App Server needs a strongly typed C# client to call Hyper Agent HTTP endpoints. Three plausible shapes:

- **NSwag generation** — full client with DTOs, request/response types, async methods. Standard .NET ecosystem.
- **Microsoft Kiota** — Microsoft's official OpenAPI client generator. Strong typing and tooling.
- **Hand-written client** — `HttpClient` + manual DTO classes. Maximum control but no schema enforcement.

## Decision

NSwag. Concretely:

1. The Hyper Agent exposes its OpenAPI document at `/v1/swagger.json` (existing NestJS Swagger setup).
2. A `nswag.json` config at the repo root defines the generator:
   ```json
   {
     "runtime": "Net80",
     "defaultVariables": null,
     "documentGenerator": {
       "fromUrl": "http://localhost:4201/v1/swagger.json",
       "output": null
     },
     "codeGenerators": {
       "openApiToCSharpClient": {
         "output": "apps/service/src/Hyper Agent/SidecarClient.g.cs",
         "className": "SidecarClient",
         "namespace": "Cinereel.Hyper Agent.Generated",
         "generateClientInterfaces": true,
         "generateDtoTypes": true,
         "useHttpClientCreationMethod": false,
         "useBaseUrl": false,
         "additionalNamespaceUsages": ["Cinereel.Infrastructure"],
         "clientClassAccessModifier": "internal"
       }
     }
   }
   ```
3. A `scripts/regen-hyper-agent-client.sh` (and Windows equivalent) runs NSwag against a running Hyper Agent to regenerate the client.
4. CI runs the script on every PR that touches `apps/sidecar/` and fails the build if the regenerated client differs from the checked-in version (i.e. the developer forgot to regenerate).
5. The App Server wraps the generated client in a hand-written `ISidecarClient` interface and adapts exception types to `RecoverableException` / `NonRecoverableException`.

## Why NSwag

- Most mature OpenAPI code generator for .NET (10+ years old, large user base).
- Native NestJS Swagger support (NestJS already emits Swagger; NSwag consumes it directly).
- Generates both client and DTOs in one pass.

## Why not Kiota

- Kiota is younger and less battle-tested.
- NSwag has better support for non-trivial OpenAPI features (e.g. nested generics, complex union types).
- Migration to Kiota is straightforward if NSwag becomes unmaintained.

## Trade-off accepted

- NSwag generates a single large `.g.cs` file. Reviewers must trust the generator. We mitigate with a CI check that forces regeneration on every Hyper Agent change.
- The generated client is `internal`. Consumers depend on a hand-written `ISidecarClient` wrapper that translates exception types and adds logging.
