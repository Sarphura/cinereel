# Logging uses Microsoft.Extensions.Logging with structured JSON to stdout and a rotating local file

The C# Application Server logs via .NET 10's built-in `Microsoft.Extensions.Logging` (MEL). Two sinks are configured:

- **Stdout sink**: `ConsoleLoggerProvider` emits structured JSON (one object per line), suitable for ingestion by Docker / journald / loki.
- **File sink**: A custom rotating `FileLoggerProvider` writes human-readable lines to `<data-dir>/logs/cinereel.log` with daily rotation, retaining 14 days.

## Context

Cinereel logs need to be:

- **Structured** for queryability (drive_key, subscription_id, sidecar_request_id should be searchable).
- **Human-readable** for users debugging their own NAS deployment.
- **Compatible** with library logs from EF Core, MonoTorrent, and ASP.NET Core (all use MEL).
- **Container-friendly** so Docker deployments can pipe stdout to a log collector.

Three plausible choices:

- **MEL only** — built-in, no extra dependency, all libraries speak it natively.
- **Serilog** — feature-rich structured logger, wide ecosystem, but adds an extra abstraction layer.
- **NLog** — older, more config-heavy.

## Decision

MEL only. Concretely:

```csharp
builder.Logging
    .ClearProviders()
    .AddJsonConsole(/* options */)
    .AddProvider(new RotatingFileLoggerProvider(/* ... */));

builder.Host.UseSerilog(); // NOT used
```

### Stdout format

JSON object per line:

```json
{"@t":"2026-07-23T22:14:33.221Z","@l":"Information","@mt":"subscription created","SubscriptionId":42,"DriveKey":"a3f5...","Category":"Cinereel.Subscription.Service"}
```

`@t` is timestamp, `@l` is level, `@mt` is message template, followed by structured properties.

### File format

```
2026-07-23T22:14:33.221Z [INF] [Cinereel.Subscription.Service] subscription created (SubscriptionId=42, DriveKey=a3f5...)
```

### Correlation ID

Each Sidecar request is logged with a `SidecarRequestId` GUID generated by the App Server's `ISidecarClient` wrapper. The wrapper also forwards the same ID as `X-Cinereel-Request-Id` to the Sidecar so the Sidecar can log it. This lets an operator correlate one request across both processes.

### Rotation

`RotatingFileLoggerProvider` rolls the log file at midnight (UTC). Old files are named `cinereel.2026-07-22.log`, `cinereel.2026-07-21.log`, etc. Files older than 14 days are deleted on rotation.

### Log levels

- Default: `Information`
- `Cinereel.Bt.Engine`: `Debug` (high frequency)
- `Cinereel.Sidecar.Generated`: `Warning` (suppresses per-request noise)
- Override via `appsettings.json` under `Logging:LogLevel:Category`

### What is NOT in V1

- Serilog or NLog.
- Log aggregation sinks (Seq, Elasticsearch, Loki).
- Per-user audit logs.
- Sensitive-data redaction (the App Server does not log DriveKeys in plaintext to stdout in production; file logs do include them for debugging).

## Trade-off accepted

- MEL's structured logging is slightly less ergonomic than Serilog's (no `ForContext`, no message-template idioms), but `LoggerMessage` source generators (built-in) cover most cases.
- JSON stdout is verbose for humans in development. The file log covers that.
- No remote log shipping; users run their own collection if they need it.
