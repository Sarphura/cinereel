# ADR-0010：流式读取原文件并持久化离线缓存任务

- 状态：已接受
- 日期：2026-09-05

## 背景

Hyper Client 已有文件列举与写删 Interface，但缺少正文读取。下载、媒体直读和离线缓存都需要处理元数据复制、正文缺块、版本变化与资源取消。Hyperdrive 的共享 Drive 对象不能随单个 HTTP 请求关闭；其 `download().done()` 使用 `Promise.allSettled`，不能独立证明所有内容已成功下载，monitor 的百分比也不能准确表达已有缓存和所有 blob 布局。

## 决策

### 统一原文件读取

`FileService` 提供固定版本的读取会话，封装元数据准备、文件描述、流式枚举、范围读取、本地完整性验证和独享资源释放。HTTP Controller 与 `DownloadTaskService` 复用这一 Interface；SDK 类型声明与实际运行时的差异集中在读取 Implementation 内。

读取会话使用独享 checkout 和 Hypercore session。响应头、正文和离线任务对应同一元数据版本；任务还分别记录元数据 fork 和已经确认的正文 fork，任一存储被截断导致原版本身份失效时都不能自动切换到新内容。ETag 同时包含正文身份，防止只改变正文时错误接受旧的 If-Range。未知远端的正文 fork 必须等签名信息就绪后确认，不能把尚未同步的初始值写入检查点。默认元数据准备和缺块等待各有 30 秒上限，整文件传输没有固定总时长限制。未知远端尚无元数据时必须等待或报错，不能假装为空 Drive。

HTTP 提供 GET、HEAD、单段 Range、ETag 与 If-Range，并允许 inline 或 attachment。传输保持背压，不在内存聚合整文件。首块失败映射为 HTTP 错误；响应开始后失败只能终止传输。Hyper Client 传递原始媒体，解码和转码不属于此 Interface。

### 离线任务是本地 I/O 状态

离线下载指将指定版本的内容缓存到 Corestore，不产生用户目录中的普通文件副本，也不建立 Cinereel Subscription 或 Publication。任务只保存 I/O 参数与执行状态，不拥有 DriveId、权限、媒体分类和业务关系；这些职责仍属于 C#。

任务支持单文件和目录前缀，根目录任务缓存全部普通文件，排除 `/.cinereel` 协议目录；协议文件通过独立 Interface 访问。直接指定协议路径的任务在执行时失败，错误码为 `reserved-path`。首次成功准备元数据后固定版本，再扫描和读取。目录枚举不跟随符号链接，只统计跳过项。目录和整盘任务属于底层内容缓存，不承担面向用户的文件清单或协议文档同步职责。

后台逐文件读取到丢弃 sink，由 Corestore 缓存块，随后验证本地完整性。进度表示处理的文件内容字节，包含读取已有缓存；它不是网络下载量。检查点只确认完整文件，恢复时重新检查缓存，未完成文件从头读取，瞬时进度可以回退。

### 持久化、恢复和控制

任务存储为 `CONFIG_DIR/download-tasks.json`，具有显式 `schemaVersion`。单写队列串行提交状态，写入临时文件并同步后原子替换。未知版本或损坏文件阻止启动任务调度，不能作为空任务列表覆盖。创建和控制操作成功响应前必须完成持久化。

状态为 `queued`、`running`、`paused`、`completed`、`failed`、`canceled`。重启把 `running` 恢复为 `queued`，继续等待执行的任务，保留暂停及终态。默认两个任务并发，每个任务顺序处理文件；网络失败最多额外重试三次，间隔 1、5、30 秒，等待期间释放执行名额。主动重试保留原版本。

暂停和取消先停止并等待当前 worker，再确认状态；两者均保留缓存。`completed` 只表示对应版本完成过本地缓存，显式清理仍可能使其失效。本次不提供自动缓存淘汰、配额或可靠空间回收。

### 共享 Drive 生命周期

共享 `DriveActivity` 同步登记文件操作及未完成任务。`queued`、`running`、`paused` 任务持有登记；终态释放。卸载、删除以及清理测试入口在存在登记时返回 `409`，开始关闭后也拒绝新登记，防止异步检查与使用之间发生竞争。

应用退出时先停止调度、取消并等待 worker、保存恢复状态，再由 `onApplicationShutdown` 关闭共享 SDK。单个请求和任务只释放自己的资源。

## 备选方案与取舍

- HTTP 和后台分别直接调用 SDK：实现起步较少，但复制版本、超时、取消和完整性检查，后续修复易产生分歧。
- 直接依赖 SDK download 和 monitor：可以减少本地读取，但现有依赖的完成语义和进度不足以满足任务契约。
- 由 C# 持久化全部下载执行状态：业务状态更集中，但 Hyper Client 无法独立完成用户要求的重启恢复，控制和恢复需要额外跨进程协调。
- 使用 SQLite 或外部任务队列：更适合大量任务和复杂查询；当前单进程本地任务采用原子 JSON，减少新的部署和数据库依赖。任务规模显著增加时需重新评估存储。

## 验证要求

覆盖 HTTP Range 边界、HEAD 不读取正文、中文文件名、取消和背压；使用真实双节点验证范围字节、完整哈希、缓存后断网读取与固定版本，并验证正文单独截断时恢复失败、ETag 改变。任务测试覆盖幂等、持久化失败、暂停和取消竞争、重试耗尽、重启恢复及 Drive 关闭互斥。Hyper Client 通过验收不表示 C# 和 Web 已完成接入。
